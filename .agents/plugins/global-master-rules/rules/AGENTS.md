# アカウント共通・最優先マスタールール（Global Master Rules for All Projects & Agents）

本ルールは、特定のプロジェクト（AI組織統括COO「ジン」等）に限らず、本アカウント・本環境で稼働する**すべてのワークスペース・すべてのAIエージェント**が、タスク着手前に**最優先で遵守しなければならない絶対原則**である。

---

## 1. 【最優先】全タスク共通・最適モデル判定 ＆ 切り替え提案・アドバイスゲート

ユーザーから作業依頼を受けた際、エージェントは実作業（ツール実行やサブエージェント起動）を開始する**前**に、必ず**「現在選択されているモデル（`Model Selection`）」**と**「依頼内容の性質・難易度」**を照合し、最適モデルとの差異がある場合は**選定理由のアドバイスを添えて切り替えを提案**すること。

### タスク特性別・最適モデル選定マトリクス（2026年11月基準）

| 領域・タスク内容 | 推奨モデル / 思考レベル | 選定理由（アドバイス基準） |
| :--- | :--- | :--- |
| **A. コーディング・デバッグ・ツール連続実行・科学数学・Blender 3D**（`bpy` / `bmesh`、ジオメトリ／シェーダーノード、リグ、リポジトリ横断改修） | **`Gemini 4 Neon (High)`**<br>（極限幾何・難航デバッグ・連続エラー時は **`XHigh`**） | Hydrogenベースの高速応答と、高いコード精度・数理推論・ツール連続実行の安定性を両立。 |
| **B. 長尺動画・音声精密解析・大容量資料の横断照合・公的議事録／法務契約書・画面GUI操作** | **`Gemini 4 Argon (Medium以上)`**<br>（案件により `Neon High` / `Carbon` も比較提示） | 長時間マルチモーダル理解・100万トークン情報探索・画面キャプチャベースのGUI操作に強み。 |
| **C. 高度なアーキテクチャ設計・難関クリエイティブ・最高品質の総合推論** | **`Gemini 4 Carbon (Medium/High)`** または **`Claude Opus/Sonnet 5.5`** | 最高水準の統合推論が必要な場合の選択肢（クォータ消費が大きいため重要局面で提案）。 |
| **D. 定型・軽量作業**（`/pc-env-sync`、単純なファイル整理・リネーム、短文作成、簡単な質問、Blenderの単発確認・移動/リネーム/単色変更） | **`Gemini 4 Hydrogen (Low/Medium)`** | 待ち時間とクォータ消費を最小化しつつ、定型タスクで十分な品質を確保可能。 |

### パターン別アクション

- **パターンA：アンダースペック警告**（`Hydrogen` 等で領域 A〜C の高難度タスクを依頼された場合）
  - いきなり低精度で着手せず、**ユーザーが「モデル選択はお任せ」「自動切替で」と委任している場合を除き**、作業前に以下を逆提案して一時停止すること：
    > ⚠️ **【最適モデルへの切り替え提案・アドバイス】**
    > ご依頼の作業は「（理由：例 `bpy` ノード構築・空間推論／長尺動画解析／横断デバッグ 等）」を伴うため、現在のモデルでは精度低下や手戻りが発生するリスクがあります。**`（推奨モデル名・思考レベル）`** が最適です（理由：〜）。
    > 1. **画面のモデル選択を推奨モデルへ切り替えてから実行する（推奨）**
    > 2. **メインはこのままにし、`swarm` ワーカーに最適実名モデル（例：`gemini-4-neon-high`）を指定して実行する（サブスク枠内）**
    > 3. **メインはこのままにし、サブエージェントを上位Tier（`Model: "pro"`）で実行する**
    > 4. **現在のモデルのまま続行する**
    > いかがいたしますか？

- **パターンB：オーバースペック（クォータ節約）提案**（`Neon` / `Argon` / `Carbon` / `Claude` 等で領域 D の軽作業を依頼された場合）
  - クォータ消費を抑えるため、作業前に **`Gemini 4 Hydrogen`** への切り替え（または `swarm` の `gemini-4-hydrogen-low` / サブエージェント `flash` 委譲）を提案すること（1ステップで即答できる単純質問は回答しつつ次回切替を案内してよい）。

- **パターンC：適正一致**
  - 現在の選択モデルがタスク難易度に最適である場合は、止めずにそのまま速やかに作業を開始する。

## 2. 最新モデル導入チェック ＆ クォータ確認機構（動的検知ルール）

ルール内の固定モデル名だけで判断が陳腐化しないよう、以下の**いずれかのトリガー**に該当した場合は **`swarm(action="models", all=true)`** を実行して現在の契約アカウントで利用可能な全モデルID・表示名・残クォータ（%）をリアルタイム照会すること（※通常チャットで毎回実行して遅延を増やさないこと）：

1. **未知モデルの検知**: ユーザーの `Model Selection` や環境通知に、本ルール未記載の新しいモデル名が登場した時。
2. **ユーザーからのモデル相談・点検指示**: 「最新モデルが来ていないか確認して」「今の作業に一番いいモデルはどれ？」「クォータ残量も踏まえて選んで」等の依頼を受けた時。
3. **定期組織監査**: `05_System_Evolution_Dept`（`/system-evolution`）の監査実行時。

### 検知時のアクション
- 未知の新モデルを検知した場合は、必要に応じて `search_web` 等で公式仕様・得意分野・料金特性を確認し、①今回のタスクに新モデルが適しているかアドバイスした上で、②本マスタールール（`.agents/plugins/global-master-rules/rules/AGENTS.md`）の選定マトリクス更新をユーザーへ提案すること。
- 推奨モデルの残クォータが著しく低下・枯渇している場合は、利用可能な代替上位モデル（または次善モデル）を残クォータ付きでアドバイスすること。

---

## 3. 自動切替委任時の `swarm` 動的モデル選択・昇格ルール（Swarm Dynamic Model Routing）

- ユーザーが「最適モデル自動切替で」「モデル選択はお任せ」等と委任した場合（またはパターンAの選択肢2を選んだ場合）、エージェントは `swarm` ツールを用いてタスク難易度に応じた実名モデル（例：`gemini-4-hydrogen-low` / `gemini-4-neon-high` / `gemini-4-neon-xhigh` / `gemini-4-argon-high` / `gemini-4-carbon-high`）でワーカーを起動できる。
- 軽量モデル（`Hydrogen` 等）で実行したワーカーが連続エラーや品質破綻を起こした場合は、`swarm(action="model")` により上位モデル（`gemini-4-neon-high` → `gemini-4-neon-xhigh` 等）へ動的に昇格させ、切り替え理由と使用モデルを最終報告に明記すること。

---

## 4. 不具合調査・デバッグ時の実証ファースト原則（推測編集禁止ゲート）

アプリ・Web UI・プラグイン・複数プロセス間の不具合を調査する際、エージェントは以下を厳守すること：

1. **推測による設定変更・再起動依頼の禁止**:
   - 原因の仮説だけで設定書き換えやキャッシュ削除、ユーザーへのアプリ再起動依頼を行わないこと。
   - 変更を加える**前**に、必ず **①対象プロセスの標準出力／標準エラー、②ブラウザ／Webview のコンソールログ、③実描画状態（スクリーンショット・実DOMテキスト・実ファイルバイト列）** を直接取得し、再現条件と真因を確定させること（`HTTP 200` やファイル存在のみで正常と判断しない）。
2. **会話途中での難易度上昇・モデル昇格ゲート**:
   - 当初は軽量タスク（領域D：`Hydrogen` 適正）として開始した会話であっても、途中で原因不明のエラー解析や複数プロセス・Electron・認証等の複合デバッグ（領域A〜C）へ移行した時点で、そのまま軽量モデルで試行錯誤を続けず、第1項のマトリクスに従い **`Gemini 4 Neon (High)`（難航時は `XHigh`）** 等への切り替え（または `swarm` 上位モデル委譲）を即座に提案すること。
3. **検証完了後の報告**:
   - 修正パッチ適用後は、構文チェック（`node --check` 等）と実際の再現条件での動作確認（エラー消失・正常描画確認）をエージェント側で完了させてからユーザーへ報告すること。
